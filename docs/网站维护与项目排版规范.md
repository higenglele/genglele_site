## 4. 项目卡片排版规范

### 4.1 网格与结构

当前项目区域有四张卡片：一张氛围视频卡 + 三张项目卡。视频卡不算项目1。

| 项目 | 当前规范 |
| --- | --- |
| 排列顺序 | 视频 → 01聚合 → 02栖居 → 03Omii |
| 小屏 | 默认1列；卡片间距12px，640px起8px |
| 中屏 | 768px起2列；卡片间距4px |
| 大屏 | 1024px起4列；网格最小高度480px |
| 项目卡 | 背景 `#212121`，圆角16px，内边距20px |
| 项目卡高度 | 默认最小360px，640px起最小400px；1024px起跟随网格等高 |
| 纵向结构 | 标题/副标题与编号 → 封面 → 功能要点 → 底部链接 |
| 底部对齐 | 卡片使用纵向flex与 `justify-between`，入口与正文间距32px |

修改共性排版应优先修改 `ProjectCard`，不要为单个项目复制一套卡片组件。

### 4.2 文案、封面与色彩

- 标题16px，颜色 `#E1E0CC`；副标题独立一行，使用灰色。编号位于右上角，格式保持 `01`、`02`、`03`。
- 封面显示比例统一为 **16:10**，宽度铺满，`object-cover object-top`，圆角12px，上间距20px。不同原图比例会裁切，重要内容需留在可见区域。
- 封面容器黑色背景和轻微白色边框；默认90%不透明度，悬停恢复100%。
- 当前每个项目保留 **3条功能要点**。建议每条只描述一个具体能力，保持长度接近；不编造使用量或业务收益。
- 要点12px，使用灰色、14px对勾图标，条目间距10px。封面与要点间距20px。
- 底部入口12px，颜色为主题 `primary: #DEDBC8`，配14px右上箭头。入口文字可因项目内容不同，例如“查看案例与 Demo”“了解产品”“查看项目”。
- 更新封面后检查桌面和手机裁切效果，不把原始文件比例等同于显示比例。

### 4.3 用户确认的交互规范

1. **三个项目入口统一使用 `target="_blank"` 和 `rel="noopener noreferrer"`。** 同站链接、哈希路由与外部链接都在新标签页打开，保留原首页。
2. 不再依据 `href.startsWith('#')` 决定是否新开页面；这曾导致项目2行为不一致。
3. **点击项目卡片链接后，卡片周围不能出现黄色/橙色光圈或描边。** 不恢复旧的 `.project-hover-card:focus-within` 黄色 `box-shadow`。
4. 保留链接正常的键盘可操作性；不要通过统一移除所有焦点样式或强制 `blur()` 来消除卡片光圈。
5. 当前仅在精细指针且支持悬停的设备上启用卡片上移6px、放大1.025倍、暗色阴影，以及其他未悬停卡片适度变暗。
6. 减少动态效果偏好下，停用相关悬停位移、缩放和过渡。
7. 当前明确入口是底部文字链接；没有把整张卡片设为点击区域。若以后调整，应统一三个项目并重新验证。

## 5. 更新网站内容的操作流程

| 步骤 | 具体操作 | 验收标准 |
| --- | --- | --- |
| 1 定位与检查 | 阅读本文，查看工作树、当前分支，`git fetch origin` 后查看远端变化 | 确认正确仓库、正确页面，清楚已有修改和线上版本 |
| 2 修改源码 | 单纯改项目文案编辑 `projectCards`；共性结构改 `ProjectCard`；样式改对应CSS；资源放入 `public/` | 改动范围与需求一致，资源路径正确，项目编号/顺序稳定 |
| 3 本地运行 | 首次安装用 `npm ci`；开发用 `npm run dev -- --host 127.0.0.1 --port 5187` | 首页与目标页面可打开；端口占用时换空闲端口并记录 |
| 4 检查与构建 | 执行下方命令；交互修改增加或运行对应回归测试 | 测试通过、构建成功、无补丁格式错误 |
| 5 预览验收 | 启动生产预览；检查1280px桌面和390px手机；必要时补1440px | 无整体横向溢出、封面裁切正确、入口可点击、新标签保留原页、无黄色卡片光圈 |
| 6 提交发布 | 在当前任务已有发布授权的范围内，核对差异并提交；同步最新主分支后按现有流程推送 | 没有混入无关改动或密钥，不覆盖远端新提交 |
| 7 线上核验 | 查看Vercel完成状态，打开正式网址验证 | 新内容出现、目标链接正常、受影响主流程通过；不能把“推送成功”直接当成“上线成功” |
| 8 留存记录 | 记录提交号、正式链接、验证内容；结构或规则变化时更新本文 | 下次维护可根据记录复现和定位 |

常用检查命令，在仓库根目录执行：

```bash
git status --short
git branch --show-current
git diff --check
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 5193
```

`npm run preview` 是持续运行的预览服务，另开终端执行其他命令。`dist/` 是构建产物，不直接编辑，也不提交到Git。

提交前查看 `git diff`，按需暂存具体文件。当前采用普通快进发布，不使用强推：

```bash
git fetch origin
git merge-base --is-ancestor origin/main HEAD
git push origin HEAD:main
```

以上在**修复已提交且当前提交包含最新 `origin/main`**时适用。祖先检查失败，应先分析并合并/变基远端更新、解决冲突并验证，再推送。

GitHub CLI已登录时，可检查部署状态：

```bash
gh api "repos/higenglele/genglele_site/commits/$(git rev-parse HEAD)/status" \
  --jq '{state: .state, statuses: [.statuses[] | {context, state, description, target_url}]}'
```

若需重新登录或授权，按用户偏好在**系统默认外部浏览器**完成，不使用内置浏览器。凭据保留在系统凭据管理中，不写入文档或源码。Safari验收已由用户取消，除非后续重新要求，不把它列为发布阻塞项。

## 6. 回归验证入口

- `npm test`：现有业务逻辑测试；不自动运行浏览器脚本。
- `tests/browser/project-links.cdp.mjs`：三项目新标签配置、卡片无黄色焦点框、项目2实际新开页并保留原首页。
- `tests/browser/social-hub-inbox.cdp.mjs`：私信静默已读、列表不回弹、回复、未读计数、手机返回与嵌入场景。
- `HOME_AGENT_ACCEPTANCE.md`：项目2既有验收参考。

浏览器脚本需要一个**独立临时Chrome配置**，开启本机CDP端口9454；不可使用日常浏览器配置或占用已有调试端口。macOS启动示例：

```bash
qa_profile=$(mktemp -d /private/tmp/genglele-browser-qa.XXXXXX)
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-extensions --no-first-run --no-default-browser-check \
  --remote-debugging-port=9454 --user-data-dir="$qa_profile" about:blank
```

保持该进程运行，在另一个终端执行（需要支持内置 `fetch` 和 `WebSocket` 的Node，当前验收使用Node 24）：

```bash
PROJECT_TEST_URL=http://127.0.0.1:5193/#works node tests/browser/project-links.cdp.mjs
INBOX_TEST_URL=http://127.0.0.1:5193/assets/demos/social-hub/index.html node tests/browser/social-hub-inbox.cdp.mjs
```

验证正式站时替换URL的协议和域名。私信脚本只会在这个临时配置中操作模拟数据；不连接真实自媒体平台。验收结束只停止自己启动的Chrome进程，不关闭用户浏览器。
